# P0-2 Tenant Isolation & Authorization Test Plan

## Purpose
Validate tenant isolation, role permissions, permission overrides, organizational scopes, write boundaries, and audit protections before moving to the next MVP phase.

## Test environment
These tests must run against a disposable Supabase database/branch. Do not create synthetic users, organizations, or financial data in production.

## Required fixtures
- Organization A
- Organization B
- User A: member of Organization A only
- User B: member of Organization B only
- Scoped User A: Organization A member with Branch A scope
- Branch A and Branch B in Organization A
- At least one financial fact for each organization/branch
- Role permission granting `view` and `import`
- Permission override records for explicit grant and deny cases

## Assertions
1. Organization A data is not visible to User B.
2. Organization B data is not visible to User A.
3. Branch A scoped user cannot read Branch B facts.
4. Organization-wide user can read allowed organization data when no restrictive scope assignment exists.
5. Role permission grants access only when membership exists.
6. Explicit deny override wins over a role grant.
7. Explicit grant override wins when membership exists and no deny is present.
8. Authenticated clients cannot directly insert into `financial_facts`.
9. Authenticated clients cannot directly insert into `audit_events`.
10. `publish_actuals_from_import` is executable by authenticated users only.
11. Publish requires the `import` organization permission.
12. Publish writes actual facts only through the controlled RPC boundary.
13. Audit records are generated by server-side mutation triggers rather than client INSERTs.

## Current automated contract test
`supabase/tests/tenant_isolation.sql` verifies the deployed schema contract and privilege boundaries without mutating production data.

## Runtime integration tests
The next step is to execute the fixture-based assertions in a disposable Supabase branch/database using authenticated sessions for User A and User B. Cross-tenant and cross-scope failures must be treated as release blockers.
